# Quality check 2026-11-01

The ten quality rules checked against the code, with evidence. Go 1.26.10, Windows 11, Intel Core
i7-13700H. No local PostgreSQL and no model download for this pass: the two tests that need them
(`TestPostgresKeywordAndVectorSearch`, `TestMatchesTheReferenceEncoder`) skip locally with their
reason and run in CI, which starts a pgvector container and fetches the pinned model.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | fixed | External calls are PostgreSQL (pgx pool) and the HTTP API. Every request has a deadline (`search/http.go`: 10 s per search, 2 s per health check); the server sets read, header, write and idle timeouts (`cmd/hsearch/main.go` `cmdServe`). Errors are returned, logged once at the handler, and answered as a generic 500. Found: connection attempts had no bound (`pgxpool.ParseConfig` leaves `ConnectTimeout` at 0 when the DSN has no `connect_timeout`, checked in pgx v5.11.0 `pgconn/config.go`), so `hsearch index`/`query`/`eval` could hang on an unreachable host. Now 10 s unless the DSN sets its own (`store.poolConfig`, `TestPoolConfigBoundsConnects`). `writeJSON` ignores the encoder error on purpose: the status line is already sent and the client has gone. No retries: a failed command or request is repeated by the caller. |
| 2 | Writes safe to retry | pass | The only write is `Store.Upsert`: `INSERT ... ON CONFLICT (id) DO UPDATE`, so re-running `hsearch index` replaces rather than duplicates; `TestPostgresKeywordAndVectorSearch` upserts a document twice and checks the count stays 3 (CI). The schema uses `IF NOT EXISTS` throughout (`Migrate`). `pgx.BatchResults.Close` returns the first error of the batch (pgx v5.11.0 `batch.go`), so a failed row is not lost. |
| 3 | No race conditions | pass | `Service.hybrid` runs the keyword query in a goroutine and hands its result back over a buffered channel; the fusion maps are local to the call. CI runs `go test -race` (no cgo locally). |
| 4 | Don't trust the clock | pass | `took_ms` and the indexing times use `time.Since` on `time.Now` (monotonic). No timestamps are stored. |
| 5 | Read before changing | pass | pgx fields used (`ConnConfig.ConnectTimeout`, `MaxConns`, `AfterConnect`) checked in the installed v5.11.0. Environment variables: `HSEARCH_DSN` (CLI default, README "How to use it") and `HSEARCH_TEST_DSN` (tests, Makefile comment and README): both documented. |
| 6 | Never break compatibility | pass | Schema, API and JSON shapes unchanged. A DSN's own `connect_timeout` still wins. `hsearch eval` now refuses a judged file with no queries, which before printed NaN scores. |
| 7 | One source of truth | pass | The `tsvector` column is generated by PostgreSQL from title and body (`GENERATED ALWAYS ... STORED`), so it cannot drift; embeddings are rebuilt by re-running `hsearch index` from the corpus file, which is rebuilt by `hsearch corpus`. Go version: `go.mod`, CI 1.26.10, README: consistent. |

Inputs: query 1..512 bytes of UTF-8, `k` 1..50, mode from a fixed set, documents bounded and UTF-8 checked, vectors finite, listen address loopback only. Found: an empty judged-query file was accepted (above). No new dependency. |

## Known limitations

- The CLI commands other than `serve` have no overall deadline on queries; they stop on Ctrl-C
  (the command context is cancelled on interrupt) and connection attempts are bounded.
- The race detector, the PostgreSQL test and the encoder reference test run only in CI.
